# PORTCULLIS

[![CI](https://github.com/Kaushik2210/PORTCULLIS/actions/workflows/ci.yml/badge.svg)](https://github.com/Kaushik2210/PORTCULLIS/actions/workflows/ci.yml)

**A real-time adversarial prompt-injection detection gateway for LLM applications.**
Think WAF, but the payloads are natural language and the protected asset is a model's
instruction hierarchy.

> **Status: Milestone 10 of 11.** The dashboard's three surfaces (live traffic, decision
> inspector, red-team console) are live and verified end to end against the real gateway and the
> real Milestone 9 eval artifacts — see [dashboard-report.md](docs/benchmarks/dashboard-report.md)
> for the live browser session that proved it, not a storyboard. The benchmark table below is
> real, generated by `just eval` against the full ~20k-row test set through the
> actually-deployed cascade. Read [eval-report.md](docs/benchmarks/eval-report.md) before
> trusting the table: it contains findings that are genuinely unflattering (the regex-only
> baseline matches the full learned system at low FPR; removing the kNN sidecar from fusion
> measurably *improves* the headline numbers; full-cascade latency is well over budget, and 85%
> of it is one unoptimised component; a generic black-box search evades the deployed detector
> 69% of the time). **L3 is a deliberate scope cut** (never had a milestone number — see
> [ADR-0007](docs/adr/0007-gateway-scope-and-mock-upstream.md)); several of M9's own named
> pieces (LLM-judge/commercial-API baselines, external red-team CI, load testing, GCG suffix
> attacks) are cut too, each for a stated reason — see
> [ADR-0010](docs/adr/0010-m9-eval-harness-scope.md); the dashboard's own cuts (durable decision
> logging, a genuinely second trained model to diff) are in
> [ADR-0011](docs/adr/0011-dashboard-scope-and-data-sources.md).

## Benchmark

Regenerated from scratch by `just eval` — full methodology, the ablation and adaptive-attack
results, and the three findings above in [eval-report.md](docs/benchmarks/eval-report.md).

| Metric | PORTCULLIS (fusion) | regex-only (L1) | `max()` baseline | `deberta-v3-base-injection` | LLM-as-judge |
|---|---:|---:|---:|---|---|
| **TPR @ 0.1% FPR** (95% CI) | 0.154 (0.145–0.166) | 0.198 (0.187–0.208) | 0.007 (0.003–0.019) | not built — [cut](docs/adr/0010-m9-eval-harness-scope.md) | not built — [cut](docs/adr/0010-m9-eval-harness-scope.md) |
| **TPR @ 1% FPR** (95% CI) | 0.191 (0.180–0.202) | 0.198 (0.188–0.208) | 0.067 (0.056–0.076) | not built — cut | not built — cut |
| AUPRC | 0.648 | 0.427 | 0.553 | not built — cut | not built — cut |
| Latency p50 / p95 / p99 | 68ms / 176ms / 381ms | — | — | — | — |
| Cost per 1k requests | not measured — no load test ([cut](docs/adr/0010-m9-eval-harness-scope.md)) | — | — | — | — |
| Test-set size (n) | 19,937 (5,696 attack / 14,241 benign) | — | — | — | — |

Accuracy on a balanced test set is deliberately absent. It is a vanity metric for this problem:
a detector that blocks legitimate security researchers is a broken product regardless of its
accuracy, which is why the headline is quoted at a fixed false-positive rate and shipped with a
bootstrap confidence interval. See [ADR-0004](docs/adr/0004-corpus-and-gated-data.md).

**Read the table honestly, not just the bold numbers.** Fusion beats `max()` by ~2.9x at 1% FPR —
the core architectural bet pays off. But the regex-only baseline matches or beats *fusion* at
both operating points, and an ablation shows removing the kNN sidecar entirely improves the
headline numbers. Full-cascade latency (68ms p50) is well over the project's own budget, and 85%
of it is one component (the kNN embedder) that never received the ONNX/INT8 treatment L2 did.
None of this is hidden in [eval-report.md](docs/benchmarks/eval-report.md) — it's the point of
publishing an eval harness instead of a single number.

## Architecture

A cost-ordered cascade of heterogeneous layers with short-circuit evaluation. Cheap layers run
first; expensive layers only see traffic the cheap ones found ambiguous.

| Layer | Role |
|---|---|
| **L0** | Normalisation and de-obfuscation. Unicode NFKC, zero-width and bidi stripping, confusable folding, layered decoding with a depth cap. Obfuscation depth is scored as signal, not merely removed. |
| **L1** | Signature and heuristic engine. Versioned YAML rules, fully explainable, zero ML. |
| **L2** | Learned multi-label classifier (ONNX, INT8) plus an embedding kNN sidecar for nearest-known-attack matching. |
| **L3** | *Cut.* LLM adjudication in an uncertainty band was in the original architecture but never got a milestone number — dropped as a deliberate scope decision at M6 rather than filling the gap silently. See [ADR-0007](docs/adr/0007-gateway-scope-and-mock-upstream.md). |
| **L4** | Conversation state machine (`NORMAL → PROBING → ESTABLISHING → EXPLOITING`). Cumulative risk with time decay, crescendo detection, role drift, topic-pivot-after-refusal — a policy-verdict modifier, not a fusion input (no multi-turn corpus exists to fit one against). See [ADR-0008](docs/adr/0008-l4-conversation-state-machine.md). |
| **L5** | Egress inspection. Canary tokens (zero-FP by construction — halts the response), secret/PII scanning and markdown-image/tool-call exfiltration detection (redacted in place, not blocked — real false-positive risk). See [ADR-0009](docs/adr/0009-l5-egress-inspection.md). |

Fusion is learned over layer scores, not a hand-tuned `max()`, and the comparison against
`max()` is published either way. Policy is `ALLOW | FLAG | SANITISE | CHALLENGE | BLOCK`, with
shadow mode as a first-class deployment option.

Rationale and rejected alternatives: [ADR-0001](docs/adr/0001-layered-cascade.md).

## What this is not

PORTCULLIS is a **mitigation**, not a **security boundary**. Prompt injection is not a bug with
a patch, and no text classifier resolves it. The threat model states plainly that an adaptive
attacker with white-box access defeats a detector of this class in the general case, and the
eval harness measures exactly that — publishing the attack success rate including where it is
bad.

It also detects **instruction subversion**, not **toxicity**. Those are different problems, and
conflating them produces a detector that flags a security researcher discussing injection while
missing a polite role-reassignment. This project's own documentation is a regression test that
must not be blocked.

Read [`docs/threat-model.md`](docs/threat-model.md) before the code.

### OWASP LLM Top 10 (2025)

Addresses LLM01 (Prompt Injection), LLM02 (Sensitive Information Disclosure), LLM05 (Improper
Output Handling), LLM06 (Excessive Agency), **LLM07 (System Prompt Leakage)** and **LLM08
(Vector and Embedding Weaknesses)**. **LLM10 (Unbounded Consumption) is explicitly not
addressed** — the two mitigations the original architecture named for it (L3 adjudication, rate
limiting) were both cut or never built, stated plainly rather than left as a stale claim. Full
mapping with per-layer attribution, and the real Milestone 9 measurements against the adaptive
adversary, are in the [threat model](docs/threat-model.md#6-owasp-llm-top-10-2025-mapping).

## Quickstart

Requires Python 3.13+, [`uv`](https://docs.astral.sh/uv/), [`just`](https://just.systems/),
Node 22+ (for the dashboard) and Docker.

```bash
git clone https://github.com/Kaushik2210/PORTCULLIS.git && cd PORTCULLIS
just install
just check
```

**How long this actually takes, measured, not guessed.** `just install && just check` — the
pure software path, no training — is a few minutes on ordinary hardware. A genuinely *working
detector* needs a trained checkpoint, and that is not fast: `just l2` (fine-tune, calibrate,
export L2) measured **~32 minutes** on this project's own CPU-only dev machine (M4), and
`just m5` (build the kNN index, fit fusion) adds several more. **This project does not claim a
five-minute path to a working detector, and does not publish trained weights to manufacture
one** — partly because it would be dishonest given the real numbers above, and partly because
the threat model (§3C) explicitly treats "an adversary with the detector's own weights" as a
real, named adversary; shipping the weights to shave setup time would hand out exactly the
capability that adversary is modelled against. Once trained, every `just demo-m*` and
`just dashboard` command is real-time.

| Command | What it does |
|---|---|
| `just check` | Lint, `mypy --strict`, and tests — the same gates as CI |
| `just bench` | Re-measure the L2 latency frontier on your machine |
| `just l2 && just m5` | Train/export L2 and fit fusion — produces the checkpoint the demos need |
| `just gateway-mock-upstream` | Start the fake LLM backend the gateway proxies to by default (no API key, no cost) |
| `just gateway-serve` | Start the real gateway (needs `just l2 m5` first) — pairs with `gateway-mock-upstream` above |
| `just demo-m6` | The Milestone 6 checkpoint: starts the gateway and mock upstream, shows a swap |
| `just demo-m7` | The Milestone 7 checkpoint: a real multi-turn conversation plus the crescendo algorithm |
| `just demo-m8` | The Milestone 8 checkpoint: a live system-prompt-leak catch plus secret redaction |
| `just up` / `just down` | Redis + Postgres via Docker Compose |
| `just test-model` / `just test-infra` | Tests needing the real checkpoint / a real Redis |
| `just eval` | Regenerate the real benchmark table (~18 min) — headline, baselines, ablations, latency, adaptive attacks |
| `just dashboard` | Start the dashboard's dev server (needs the gateway running separately) |
| `just dashboard-check` | TypeScript strict + ESLint + Vitest — the frontend's `just check` |

## Lessons learned

Real findings from building this across 11 milestones, not retrospective flattery.

- **The same contention-contamination bug recurred four times** (ADR-0002's original latency
  spike, M4's L2 training report, M5's fusion latency re-measurement, M10's dashboard
  eval-scores re-run) and was caught freshly each time by comparing against the last clean run
  before publishing, never by assuming a re-run is safe just because the code didn't change. A
  hybrid P/E-core laptop under real background load produces numbers 3-11x worse than idle, and
  nothing in the code or the test suite tells you that happened — only a diff against a prior
  clean measurement does.
- **The eval harness was the right thing to build, and it was uncomfortable in exactly the way
  that means it worked.** A single accuracy number would have hidden that regex-only matches the
  full learned system at low FPR, that removing the kNN sidecar from fusion improves the
  headline metric, and that a generic black-box search evades the deployed detector 69% of the
  time. All three are real, all three are published, and none of them would exist as findings if
  the harness had been scoped to "compute the headline number and stop."
- **Scope cuts made honestly compound.** L3 (LLM adjudication) was cut at M6 rather than papered
  over, but two later documents (the OWASP mapping, this README) still claimed capability from
  it until a deliberate re-read against the Definition of Done caught the drift. A cut recorded
  once in an ADR does not stay correct everywhere it's referenced — every downstream claim needs
  the same re-check, and staleness here is a documentation bug with the same severity as a code
  bug, not a lesser one.
- **An async test that hangs forever is a real bug in the test, not a flaky test to retry.** The
  M10 SSE round-trip test deadlocked because Starlette's disconnect-detection races an in-process
  ASGI transport in a way that only manifests for a generator that runs forever by design — a
  `pytest-timeout` retry would have hidden a genuine, explainable interaction instead of
  surfacing it. `asyncio.wait_for` plus reading the actual traceback found the real cause in
  minutes; a longer timeout would have found nothing.
- **Windows is a first-class target, not an afterthought, and it repeatedly changed the plan.**
  FAISS over hnswlib (no prebuilt wheel), PowerShell 5.1's lack of `&&` and its per-line shell
  invocation in `just` recipes, and the CI matrix running both OSes were all decided because this
  project's own dev machine is Windows — none of them would have surfaced building on Linux only,
  and a Linux-only CI would have shipped at least one of them broken.

## Repository layout

```
packages/core/       detection cascade, layer interfaces, fusion, policy
packages/gateway/    FastAPI proxy + standalone detect API
packages/training/   data pipeline, training, calibration, ONNX export
packages/eval/       harness, baselines, ablations, adaptive attacks
packages/client/     typed Python SDK

rules/               versioned YAML signatures
```
